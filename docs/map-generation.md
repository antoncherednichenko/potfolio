# Генерация и редактирование карты

Готовая карта — [`public/assets/game/world.json`](../public/assets/game/world.json):
50×50 тайлов по 16×16 пикселей, то есть 800×800 пикселей. Это ферма с домом,
прудом, огородом, деревьями и связной сетью дорожек. Исходный `tile-map.json`,
изображения и приложение не изменены; новая карта ещё не подключена к сцене игры.

## Файлы и команды

Все команды выполняются из корня проекта с Node.js 24 и npm 11. Зависимости
устанавливаются через `npm ci`. Скрипты используют уже имеющиеся `sharp`
(транзитивная зависимость Next.js) и `prettier`; новых пакетов не добавлено.
После обновления зависимостей проверьте доступность `sharp`: скрипты зависят от
него напрямую, хотя сейчас он присутствует через Next.js.

| Файл                                            | Назначение                                                                                           |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `public/assets/game/assets-manifest.json`       | Рекурсивный каталог: форматы, размеры, SHA-256, типы изображений, подтверждённые и проверочные сетки |
| `public/assets/game/semantic-catalog.json`      | Значения выбранных локальных ID, координаты, правила сборки объектов и контракт слоёв                |
| `public/assets/game/manual-classification.json` | Неопределённые назначения, соединения и диапазоны анимаций, требующие ручной проверки                |
| `public/assets/game/world.json`                 | Редактируемая карта Tiled с встроенными описаниями тайлсетов                                         |
| `public/assets/game/validation-report.json`     | Результат последнего запуска структурной проверки и проверки маршрутов                               |
| `public/assets/game/previews/`                  | Общий обзор, пронумерованные тайлсеты, обычный и отладочный рендеры карты                            |
| `scripts/maps/catalog.mjs`                      | Редактируемый источник семантических правил и перечня ручной классификации                           |
| `scripts/maps/generate-world.mjs`               | Детерминированная компоновка локации и экспорт трёх JSON-файлов                                      |

Анализ изображений и обновление превью:

```sh
node scripts/maps/analyze-assets.mjs
```

Анализ обновляет контрольные суммы каталога. Чтобы проверить сохранность уже
учтённых оригиналов, сначала запустите валидатор с существующим манифестом.
Превью — производные материалы для просмотра; они не используются картой как
новая игровая графика. Генерируемые каталоги, `world.json` и `previews/**`
исключены из повторного сканирования.

Первичная генерация, если `world.json` ещё отсутствует:

```sh
node scripts/maps/generate-world.mjs
```

Поставляемая карта уже существует, поэтому эта команда откажется её перезаписывать.
Для пересборки сначала сохраните копию ручных правок вне `public/assets/game`, затем:

```sh
node scripts/maps/generate-world.mjs --overwrite
node scripts/maps/validate-world.mjs
node scripts/maps/render-world.mjs
node --test scripts/maps/*.test.mjs
```

Генератор сверяет используемые изображения с SHA-256 манифеста и откажется
работать при их изменении. `--overwrite` перезаписывает `world.json`,
`semantic-catalog.json` и `manual-classification.json`; он не импортирует правки
из Tiled обратно в генератор. Для проверки и рендера ручных правок запускайте
только две соответствующие команды. Валидатор и рендерер также принимают путь
к карте первым аргументом; относительные пути к изображениям должны оставаться
корректными относительно этой карты.

Проверка побайтного соответствия исходному шаблону без записи файлов:

```sh
node scripts/maps/generate-world.mjs --check
```

После ручных правок эта команда ожидаемо сообщает о различиях. Для проверки
отредактированной карты используйте `validate-world.mjs`. Текущие правки в
`world.json` сохранены: точка старта перенесена, маркер жителя удалён. Генератор
проверен отдельно на изолированной копии; `--overwrite` восстановит его шаблон.

## Работа в Tiled

Откройте `public/assets/game/world.json` через **File → Open**. Отдельные `.tsx`
или `.tsj` не нужны: описания девяти тайлсетов встроены в JSON. Изображения
подключены относительными путями, например `Tiles/PathTile.png`; переносите
карту вместе с исходными папками. Сохраняйте её как JSON с данными Tile Layers
в виде массива чисел.

| Слой             | Тип          | Содержимое                                             |
| ---------------- | ------------ | ------------------------------------------------------ |
| Ground           | Tile Layer   | Сплошная трава                                         |
| GroundDetails    | Tile Layer   | Пруд, грядки, мелкая растительность                    |
| Roads            | Tile Layer   | Дорожки с согласованными краями и углами               |
| Decorations      | Tile Layer   | Заборы, камни, сундук, нижние части деревьев и фонарей |
| Buildings        | Tile Layer   | Нижняя часть дома                                      |
| Foreground       | Tile Layer   | Крыша, кроны и верхние части фонарей                   |
| CollisionObjects | Object Layer | Прямоугольные препятствия и границы мира               |
| NPCs             | Object Layer | Точки размещения персонажа и курицы                    |
| Interactables    | Object Layer | Дверь, сундук, место рыбалки и две грядки              |
| Triggers         | Object Layer | Области событий                                        |
| PlayerSpawns     | Object Layer | Стартовая точка игрока                                 |

Координаты столбцов и строк в превью начинаются с нуля. Локальный номер тайла:
`localId = row * columns + column`. Число в массиве слоя — глобальный ID:
`gid = tileset.firstgid + localId`; `0` означает пустую клетку. Не переносите
`firstgid` из старой карты: он относится к конкретному набору тайлсетов новой
карты. Геометрия объектов, `approachX` и `approachY` задаются в пикселях;
точка `(24.5, 28.5)` в единицах тайла соответствует `(392, 456)` пикселям.

Перемещая дом, дерево или интерактивный предмет, перемещайте связанные части
графики, прямоугольник коллизии и логический объект вместе. `approachX/Y`
задают доступную точку подхода к взаимодействию. Типы действий (`open-chest`,
`fish` и другие), размеры препятствий и роли NPC — авторские данные карты,
а не свойства, доказанные одним изображением.

Текущий валидатор поддерживает конечные ортогональные карты 50×50, сетку 16×16,
шесть видимых тайловых слоёв в указанном порядке и пять объектных слоёв.
Поддерживаются встроенные тайлсеты без отступов и промежутков, неотражённые
тайлы, точки и прямоугольники без вращения. Группы, бесконечные карты,
внешние тайлсеты, сжатые данные, перевороты тайлов, полигоны, эллипсы и анимации
нужно сначала добавить в генератор, валидатор и рендерер. Это ограничение
данной системы проверок, а не возможностей Tiled.

## Изменение генерации и подключение Phaser

Редактируйте `scripts/maps/catalog.mjs`, когда уточняете назначение тайлов:
добавляйте проверенный локальный ID, его смысл и правило сборки, затем
обновляйте соответствующую запись ручной классификации. В `generate-world.mjs`
меняется планировка: `addRoad` задаёт участки дорожек, `terrainRectangle` —
берега и грядки, `stamp` — целые многотайловые объекты, а `collision`,
`interact` и `object` — игровую разметку. Края дорожек выбираются по соседям;
случайные ID для заполнения окружения не используются.

В проекте установлен Phaser **4.2.1**. Загрузка графики будущей сцены может
выглядеть так; этот пример не добавлен в приложение:

```js
const worldImages = [
  ['grass', 'Tiles/GrassMiddle.png'],
  ['path', 'Tiles/PathTile.png'],
  ['water', 'Tiles/WaterTile.png'],
  ['farm', 'Tiles/FarmLandTile.png'],
  ['house', 'Outdoor decoration/HouseWoodBaseBlue.png'],
  ['oak', 'Outdoor decoration/OakTree.png'],
  ['fence', 'Outdoor decoration/Fences.png'],
  ['chest', 'Outdoor decoration/Chest.png'],
  ['decor', 'Outdoor decoration/OutdoorDecor.png'],
];

// В preload() сцены:
this.load.tilemapTiledJSON('world', '/assets/game/world.json');
for (const [name, image] of worldImages) {
  this.load.image(name, `/assets/game/${image}`);
}

// В create() после завершения загрузки:
const map = this.make.tilemap({ key: 'world' });
const tilesets = map.tilesets.map(({ name }) => {
  const tileset = map.addTilesetImage(name, name);
  if (!tileset) throw new Error(`Missing tileset: ${name}`);
  return tileset;
});
map.layers.forEach((layer, index) => {
  map
    .createLayer(layer.name, tilesets)
    .setDepth(layer.name === 'Foreground' ? 20 : index);
});
const spawns = map.getObjectLayer('PlayerSpawns').objects;
```

Игроку предназначена глубина `10`, между основными слоями и `Foreground`.
Object Layers читаются через `getObjectLayer`; Phaser не создаёт из них
коллизии, обработчики действий, события и анимации автоматически. Для этого
нужна отдельная реализация в `src/game/`, включая физические тела препятствий
и игрока. Текущий `Player` перемещается вручную и ещё не обрабатывает
`CollisionObjects`. NPC в карте — только логические маркеры (`markerOnly`),
поэтому в графическом рендере персонажи не появляются.

## Проверки и границы результата

Валидатор проверяет структуру, размеры, ID/GID, пути, пиксели используемых
тайлов, контрольные суммы оригиналов и доступность маршрутов от старта.
Поиск пути идёт по четырём соседям; любая клетка, пересекающая прямоугольник
коллизии, считается закрытой. Проверяются все дорожки, свободные клетки,
точки NPC, подходы к интерактивным объектам и триггеры. Такой анализ не
заменяет проверку движения конкретного физического тела в Phaser.

`render-world.mjs` собирает изображение непосредственно из JSON и оригинальных
тайлов. `previews/World.png` показывает графику; `WorldDebug.png` добавляет
сетку и разметку: красный — препятствия, жёлтый — взаимодействия, фиолетовый —
NPC, голубой — триггеры, белый — старт. Поле `visualReview` в машинном отчёте
намеренно не объявляет автоматическую структурную проверку визуальной.
Отдельные результаты проверки установленными Tiled и Phaser записываются
в `previews/compatibility-report.json`; редакторское GUI-тестирование и
игровое прохождение следует отличать от CLI-рендера и разбора JSON.

Итоги выполненных проверок: [map-validation-report.md](map-validation-report.md).
Все 23 исходных PNG, `tile-map.json` и `.tiled-project` совпали с исходными
контрольными суммами. Служебный `.tiled-session` изменился во время работы
редактора/проверок; его исходный хеш сохранён в манифесте, а изменение отмечено
отдельным предупреждением в отчётах. Этот файл не восстанавливался по догадке.

Формат основан на официальной [спецификации JSON Tiled](https://doc.mapeditor.org/en/stable/reference/json-map-format/)
и [правилах глобальных ID](https://doc.mapeditor.org/en/stable/reference/global-tile-ids/).
Справка по загрузке и созданию слоёв: [Phaser Tilemap API](https://docs.phaser.io/api-documentation/class/tilemaps-tilemap).
Совместимость с установленной версией Phaser проверяется также её локальным
парсером `node_modules/phaser/src/tilemaps/parsers/tiled/`.
